## 1. 通用约定

- 时间：存储 ISO-8601 带时区字符串（Asia/Shanghai），字段 `*_at` 为抓取时间，`*_time` 为数据业务时间。
- 主键：自增整数 `id` 或业务唯一键；对外 API 使用字符串 ID。
- 所有数据表包含 `created_at`、`updated_at`。
- 所有外部数据表包含溯源字段（见 07）：`source_id`、`quote_time`/`published_at`、`fetched_at`、`quote_kind`、`is_realtime`、`delay_seconds`、`license_status`、`commercial_ok`、`data_unavailable_reason`。
- 禁止删除历史事实表（公告/新闻/行情/预测记录）；采用状态标记。
- 金额：人民币分（整数）存储，展示时格式化；比率用小数（如 0.10 表示 10%）。

## 2. 表清单

### 2.1 市场基础（meta）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `exchanges` | 交易所 | code(SSE/SZSE/BSE)、name_zh、name_en、timezone |
| `boards` | 板块 | exchange_code、code(MAIN/STAR/CHINEXT/BSE)、name_zh/en |
| `securities` | 证券主数据 | code、exchange、board、security_type(STOCK/ETF/CB)、name_zh/en、listing_date、status、total_shares、float_shares、updated_from |
| `security_status_history` | 状态历史 | security_code、status（NORMAL/ST/*ST/DELISTING/SUSPENDED）、effective_from、effective_to、source |
| `trading_calendar` | 交易日历 | trade_date、is_trading_day、source_id、year、note（调休/节假日） |
| `trading_sessions` | 交易时段 | exchange、board、session_type(OPEN_AUCTION/CONTINUOUS/CLOSE_AUCTION/AFTER_HOURS)、start_time、end_time、cancel_allowed、effective_from、effective_to |

### 2.2 规则库（rules）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `rule_sets` | 规则集（按交易所/板块/证券类型/状态/上市阶段） | version_id(FK)、exchange、board、security_type、risk_flag、listing_phase |
| `rule_versions` | 规则版本 | id、version_code（如 SSE-2026.07.06）、doc_no、publish_date、effective_from、effective_to、source_url、checksum、status(ACTIVE/RETIRED/PENDING) |
| `rule_parameters` | 规则参数键值 | rule_set_id、key、value_type、value_json、unit、description |
| `rule_clauses` | 条款实施状态 | rule_version_id、clause_no、title、status(EFFECTIVE/PENDING)、effective_from、note |
| `rule_sources` | 官方来源 | rule_version_id、name、url、retrieved_at、sha256 |

> 规则库的**源头文件**存于 `backend/app/rules/library/<version>/*.json`，启动时加载并校验 JSON Schema，同步写入 DB 供查询/审计。

## 3. 索引与性能

- `quote_snapshots(security_code, quote_time desc)`、`kline_daily(security_code, trade_date)`。
- `news_items(published_at desc)`、`announcements(security_code, published_at desc)`。
- `trading_calendar(trade_date)` 唯一索引；`rule_versions(effective_from, effective_to)`。
- `ai_tasks(status, created_at)`；`alerts(triggered_at desc, level)`。
- WAL 模式下读写分离；批量写入使用事务，单批 ≤ 500 行。

## 4. 数据保留与备份

| 数据 | 保留策略 |
|---|---|
| 行情快照 | 滚动保留 90 天（可配置）；日K 长期 |
| 新闻/公告 | 元数据长期；摘要长期 |
| 抓取日志 | 保留 30 天 |
| AI 分析/预测 | 长期（用于准确率统计） |
| 备份 | 启动前 + 每日；保留最近 30 份；`backups/` 与 `data/backup/` |

## 5. 迁移策略

- 迁移脚本命名：`0001_init.sql`、`0002_add_xxx.sql`，启动时按版本顺序执行，记录 checksum。
- 迁移前自动备份数据库。
- 破坏性迁移（删列/改类型）必须提供回滚脚本与变更记录。

## 6. 数据字典维护

- 新增表/字段必须同步更新本文件与 07 号文档的溯源字段说明。
- 数据源适配器只写本文件定义的表；禁止旁路写入未登记表。
