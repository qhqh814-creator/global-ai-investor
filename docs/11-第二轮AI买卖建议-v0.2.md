## 1. 本轮新增功能

### 1.1 AI 投资建议（买入候选 / 持仓卖出依据）

- 新闻与公告 AI 分析（DeepSeek/Ollama）→ 股票关联 → 证据化建议。
- **买入候选**：近 14 天正向 AI 分析（重要性 L2–L4）+ 可关联到具体 A 股代码 → 按证据权重排序，展示事件摘要、原文引用、来源链接、数据时间、模型与置信度。
- **持仓建议**：针对模拟持仓，聚合负向 AI 分析（L2–L4）+ 持仓风险规则（浮亏 >8%），输出 `SELL / REDUCE / HOLD`；无负向证据时明确“未发现卖出依据”，不编造原因；行情缺失时明确“无法计算，不下结论”。
- 无证据 → **不产生建议**（页面显示“暂无，证据不足”）。

### 1.2 股票关联（确定性，不依赖模型猜测）

- 公告直接使用 `sec_code`；新闻匹配 6 位代码或证券简称（与 `securities` 主数据比对）。
- 关联结果写入 `news_stock_links`，可审计。

### 1.3 数据模型与接口

| 新增 | 说明 |
|---|---|
| `news_stock_links` | 新闻/公告 ↔ 股票代码、匹配方式、置信度 |
| `recommendation_runs` | 每次建议运行参数、模型、统计 |
| `ai_recommendations` | 建议类型（BUY/HOLDING）、动作、置信度、理由、证据链、行情快照、持仓快照、模型、状态 |
| `POST /api/ai/stock-links/refresh` | 重建股票关联 |
| `POST /api/ai/recommendations/run` | 生成买入候选与持仓建议（旧建议标记 SUPERSEDED，保留历史） |
| `GET /api/ai/recommendations?reco_type=BUY\|HOLDING` | 查询当前有效建议 |
| `GET /api/ai/recommendations/{id}` | 单条详情 |
| `POST /api/settings/ai-key` | DeepSeek Key 用 Windows DPAPI 加密保存（不返回、不写日志） |

### 1.4 界面

- 新增“AI投资建议”页面：买入候选、持仓建议、理由、证据链（原文引用+链接+时间+模型）、行情 provenance、免责声明。
- 设置页新增“AI 服务”状态（DeepSeek/Ollama 可用性）与 DPAPI 加密的 Key 输入。
- 驾驶舱“AI投资机会”卡片优先显示 AI 买入候选数量，回退到规则初筛。

## 2. 实测结果（2026-11-08）

- 使用 **DeepSeek deepseek-chat**（Key 已通过 `/models` 校验，DPAPI 加密保存）对 16 条关键公告/新闻做 AI 分析；证据校验通过的分析进入建议。
- 当前生成：**3 只买入候选**（600959、603099、600362），每条均带原文引用与来源链接；**3 条持仓建议**（000520 SELL、002036 HOLD、600000 HOLD）。
- 示例：600959 买入候选来自巨潮公告《江苏有线关于控股股东增持股份计划实施完毕暨增持结果的公告》（L2，原文引用可点开）；000520 SELL 来自《关于收到中国证监会立案告知书的公告》（L4 负向，模拟持仓 100 股）；002036 的诉讼公告被 DeepSeek 判为 L1 中性 → HOLD，页面明确“未发现卖出依据”。
- 买卖建议不构成投资建议；数据为第三方未授权快照/公开公告，带来源标注。

## 3. 已知问题与限制

1. **DeepSeek Key 已配置并校验通过**：`/models` 返回 200，DeepSeek 状态“可用”；Key 使用 Windows DPAPI 加密保存在本机，不写日志、不进入 Git。若 Key 失效，设置页会显示“不可用”，可在“设置 → AI 服务”替换。
2. 买入候选目前基于“单条正向分析即可入选”；后续应加入多来源一致性、行业/估值、风险信号抑制与回测验证。
3. 建议聚合器是确定性的（不在聚合阶段调用大模型编造文本），避免新增幻觉；AI 只负责原始新闻分析。
4. 新闻/公告仍为公开来源，未取得实时行情授权；界面已标注“第三方快照·非实时/未授权”。
5. 历史 AI 记录中存在旧规则下的短证据（如 2 字 quote），新规则只影响新分析；后续将做存量校验标记。
